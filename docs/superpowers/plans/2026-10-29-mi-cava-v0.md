# Mi Cava V0 — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PWA local-first (español) para gestionar una cava de hasta 250 botellas: stock en un toque, semáforo de apogeo, diario de descorches, import/export JSON y CSV, escáner de etiquetas opcional.

**Architecture:** SPA React + Vite que se instala como PWA. Cuatro capas con dependencias en un solo sentido: `features/` → `domain/` (reglas puras) → `db/repo.ts` (única puerta a datos) → Dexie/IndexedDB. `services/` contiene import, export y OCR. Stock e historial son **derivados** de un journal de eventos, nunca almacenados.

**Tech Stack:** React 19.3.1, TypeScript 5.9.3, Vite 8.3.5, Tailwind CSS 4.3.3 (`@tailwindcss/vite`), Dexie 4.4.7, papaparse 5.7.0, vite-plugin-pwa 2.0.0, Vitest 5.0.5 + fake-indexeddb 6.2.6, ESLint 10.13.0 + typescript-eslint 8.72.1 + eslint-plugin-react-hooks 7.1.1, sharp 0.35.5 (solo dev, para generar iconos).

**Spec:** `docs/superpowers/specs/2026-10-29-cava-design.md`

## Global Constraints

- Directorio del proyecto: raíz de este repositorio (hoy solo contiene `docs/`). Repo git se inicializa en la Tarea 1.
- **Windows/PowerShell: invocar `npm.cmd`, nunca `npm`** (la política de ejecución bloquea `npm.ps1`). Scripts: `npm.cmd run <script>`.
- Node ≥ 20 (la máquina tiene 24.20.0). Sin backend, sin Docker, sin SQLite.
- UI en español (es-ES), fechas `dd/mm/aaaa`, moneda única EUR. Textos en un solo sitio por pantalla, sin librería de i18n.
- Tokens de color exactos (spec §12): `--bg #0F0D0C`, `--surface #191614`, `--surface-2 #221D1A`, `--border #2E2824`, `--text #F2EDE7`, `--muted #A69C92`, `--wine #7A2233`, `--gold #C2A369`; claro: `#FAF8F5 / #FFFFFF / #F1EDE7 / #E2DCD3 / #1B1815 / #6B625A / #8A2436 / #8A6D2F`. Semáforo: verde `#4E8A5A`, ámbar `#C08A2E`, rojo `#A6413A`, gris `#6B625A`.
- Tema oscuro por defecto; `localStorage['micava.theme'] = 'dark' | 'light'`.
- Clave del escáner en `localStorage['micava.geminiKey']`. Nunca en código, nunca en el export.
- Identificadores: `crypto.randomUUID()`. Fechas de evento: ISO 8601 con hora (`new Date().toISOString()`); `purchasedAt`: `YYYY-MM-DD`.
- **Nunca se almacena stock ni historial**: `stock = Σ events.delta`, historial = descorches activos. No existe `deletedAt` ni borrado de vinos.
- Ventana por defecto: `drinkFrom = vintage + 3`, `drinkUntil = vintage + 12`; NV → ambos `null`.
- Clave de duplicado: `normalize(name) | (vintage ?? 'NV') | normalize(winery)`.
- Objetivos táctiles ≥ 44 px; todo badge de semáforo lleva icono + texto, nunca solo color.
- Cero diálogos modales para `+1` / `−1`. Toda acción reversible ofrece "Deshacer" en el toast.
- Un vino con stock 0 y descorches reales vive en Historial; sus notas nunca se pierden.
- Cambios de stock siempre pasan por `repo`; ninguna pantalla importa Dexie.
- Cada tarea termina con `npm.cmd run typecheck && npm.cmd run lint && npm.cmd run test` en verde y un commit.

## Review Focus

Entradas que el spec no nombra y que romperían la app en manos de un usuario real. Cada una tiene su test en la tarea indicada.

1. **Precio con formato europeo** (`"1.234,50 €"`, `"12,50"`): debe dar `123450` céntimos, no `1.2345` ni `NaN` (Tarea 14).
2. **CSV con comillas, comas y saltos de línea** en el nombre o las notas: la ida y vuelta debe devolver el mismo texto (Tarea 13).
3. **Mismo nombre y añada con bodega distinta o vacía**: no se fusiona a ciegas, se marca "posible duplicado" (Tareas 4 y 14).
4. **Añadas raras** (`0`, `1001`, `NV`, vacía, `20199`, `abc`): `1001`/`NV`/vacía → NV válido; el resto de no enteros o fuera de `1900…año+1` → error de fila, nunca un vino con año imposible (Tareas 3 y 14).
5. **Doble toque en `−`**: el stock nunca baja de 0 y el segundo toque no crea un descorche fantasma (Tarea 5).
6. **Fecha ambigua `05/03/2026`**: se resuelve con el selector de la pantalla de mapeo, jamás adivinando (Tarea 14).
